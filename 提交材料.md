## 02 项目摘要 · 一句话简介（175/180）

```
Verification that scales with ambiguity: a clear reading settles early, an ambiguous one climbs a tier ladder, and one that never clears is reported inconclusive, not guessed.
```

---

## 03 项目概览 · 描述（975/1000）

```
Reads a measurement off sources, compares it with a threshold through a grey zone, and spends more verification only near the boundary.

For SLA caps, latency budgets, concentration limits and emissions ceilings, where a false PASS is costly.

The question is not is it true but how far from the limit is it. PASS needs even the worst reading to clear the limit; FAIL needs even the best to breach it. Anything between climbs the ladder instead of being guessed.

Up to three source tiers, each judged only when every source in it is read, so no verdict rests on a partial tier. A check that never clears is INCONCLUSIVE.

The model answers one narrow question: what value of FIELD in UNIT this page reports. A reading is dropped unless the number occurs as a whole token in the page and the unit is written there, so 50 is never confirmed by a page saying 1500.

Every reading names who supplied it. The owner sets who may supply evidence and may strike a reading. 62 tests.
```

Fixed both.

Early settlement: a tier is judged only once every source in it is read. A partial tier returns GATHERING, so no verdict rests on one. The unread sources are exactly those that could widen the spread and force escalation.

## 修复说明（技术细节）

### 1. Early settlement

原 `_assess` 在 `n >= min_agree` 时**立即定论**，哪怕档位里还有来源没读。后果：3 个来源读了 2 个（80、82）就 `PASS`，第三个（98）本可把 spread 撑过灰区从而该升档。

现在：`filled < len(names)` 一律 `GATHERING`，**档位读完才判定**。

```
before:  read A(80), B(82)   ->  spread 2  ->  PASS        ← 第三个被忽略
after:   read A(80), B(82)   ->  GATHERING
         read C(98)          ->  spread 18 > grey 5  ->  ESCALATED
```

### 2. Trust policy

| 能力 | 方法 | 约束 |
|---|---|---|
| 指定谁能供证据 | `open_check(..., policy)` | `OPEN` / `CURATED` |
| 增删读者 | `set_reader(check_id, addr, allowed)` | 仅 owner，且 check 未定论 |
| 每条读数留痕 | 读数记录 `reader` 地址 | 自动 |
| 作废可疑读数 | `reject_reading(check_id, tier, i, reason)` | 仅 owner，且 check 未定论；档位随后重判 |

**关键**：这些能力都不能用来制造结论——决定结论的检查（整词锚定、单位匹配、`min_agree`、灰区）完全没变，证据不足仍然给 `INCONCLUSIVE`。
